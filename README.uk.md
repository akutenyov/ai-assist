# AI Assist

Основний код організовано в пакеті `console_app`: окремі модулі відповідають за UI, Groq API, історію чатів, файли, логування та контекст діалогу. Файл `ai_assist.py` лишається короткою точкою запуску, тому команда `python ai_assist.py` не змінюється.

Консольний AI-асистент українською мовою. Програма працює через Groq Compound Mini та, коли питання потребує актуальної інформації, автоматично виконує веб-пошук.

## Можливості

- діалог у командному рядку;
- збереження короткого й обмеженого за розміром контексту розмови;
- автоматичний веб-пошук для погоди, новин та інших актуальних запитів;
- позначка `[Використано веб-пошук]` і до п’яти URL джерел, якщо Groq звертався до інтернет-джерел;
- відображення залишку ліміту запитів і токенів після відповіді, коли Groq передає ці дані;
- команди очищення історії та завершення роботи;
- автоматичне локальне збереження кожного діалогу у JSON-файл;
- кольорове консольне оформлення, Markdown-відповіді, таблиці джерел і квоти;
- аналіз локальних текстових документів і таблиць після явного підтвердження;
- API-ключ зберігається локально у `.env`, а не в Python-коді.

## Вимоги

- Python 3.10 або новіший;
- обліковий запис Groq і API-ключ;
- доступ до інтернету.

## Встановлення

Відкрийте PowerShell у каталозі проєкту:

```powershell
cd D:\Python\my_progs\ai_assist
python -m pip install -r requirements.txt
```

## Налаштування API-ключа

1. Створіть ключ на [Groq Console](https://console.groq.com/keys).
2. Відкрийте файл `.env` у корені проєкту.
3. Заповніть значення `GROQ_API_KEY` без лапок:

```env
GROQ_API_KEY=ваш_ключ_Groq
GROQ_MODEL=groq/compound-mini
SYSTEM_PROMPT=Ти корисний та точний асистент.
```

Не надсилайте ключ у чат і не додавайте `.env` до Git. Файл уже виключено через `.gitignore`.

## Запуск

```powershell
cd D:\Python\my_progs\ai_assist
python ai_assist.py
```

Приклад запиту з пошуком актуальних даних:

```text
Знайди прогноз погоди в Калуші на 16 серпня 2026 року.
```

Програма автоматично передає моделі поточну локальну дату та день тижня, тому запит на кшталт `16-08` інтерпретується відносно дня запуску. Для найточнішого прогнозу все одно варто вказувати місто, рік і слова «сьогодні» / «завтра».

Інтерфейс використовує бібліотеку `rich`: відповідь відображається в окремій панелі з підтримкою Markdown, під час запиту видно індикатор очікування, а джерела, історія і залишок квоти показуються в таблицях.

## Команди в чаті

| Команда | Дія |
| --- | --- |
| `help` або `/help` | Показати довідку. |
| `clear` або `/clear` | Очистити контекст поточного діалогу. |
| `/file` | Показати підтримувані формати та обмеження. |
| `/file <шлях>` | Підготувати локальний файл для вашого наступного запиту. |
| `/remove-file` | Прибрати підготовлений файл. |
| `/exit`, `/quit` або `/q` | Завершити програму. |

## Обробка локальних файлів

Перед додаванням файла команда `/file <шлях>` показує підтримувані формати, обмеження та запитує підтвердження. Приклад:

```text
/file D:\Документи\звіт.pdf
```

Після підтвердження введіть завдання, наприклад: `Стисло підсумуй документ і назви три ризики.` Файл використовується лише для наступного запиту, після чого автоматично прибирається з пам’яті. Для скасування до запиту використовуйте `/remove-file`.

Підтримуються `.txt`, `.md`, `.py`, `.json`, `.csv`, `.log`, `.yaml`, `.yml`, `.xml`, `.html`, `.pdf`, `.docx` і `.xlsx`. PDF має містити текстовий шар: скановані сторінки без OCR не підтримуються. З Excel зчитуються значення максимум перших 200 непорожніх рядків. Фото, аудіо й відео не підтримуються поточною текстовою моделлю `groq/compound-mini`.

Максимальний розмір файла — **5 МБ**. До Groq надсилається не оригінальний файл, а витягнутий текст, обмежений **4 500 символами**. Це запобігає помилці `413`, але означає, що великі документи аналізуються не повністю. Текст вибраного файла надсилається до Groq і записується в локальну історію чату; не додавайте конфіденційні дані.

## Як працює веб-пошук

Використовується модель `groq/compound-mini`. Вона самостійно вирішує, чи потрібен веб-пошук. Для простих запитів, наприклад «порахуй 2 + 2», пошук зазвичай не запускається. Для новин, погоди або поточних подій він має запускатися автоматично. Після відповіді програма показує до п’яти унікальних джерел із результатів пошуку.

Програма надсилає system prompt і останні шість ходів діалогу. Кожне повідомлення обмежене 6 000 символами; середина надто довгого тексту позначається як скорочена. Це не дає історії нескінченно зростати та знижує ризик помилки `413 Request Entity Too Large`.

Після кожної успішної відповіді програма показує залишок запитів і токенів із заголовків відповіді Groq. Це ліміт для поточного вікна, встановленого API (наприклад, на хвилину), а не гарантовано добовий баланс. Якщо API не надіслав заголовки, буде виведено відповідне повідомлення.

## Структура проєкту

| Файл | Призначення |
| --- | --- |
| `ai_assist.py` | Основна консольна програма та звернення до Groq. |
| `config.py` | Завантажує локальні змінні з `.env`. |
| `.env` | Ваші локальні налаштування і секретний API-ключ. |
| `requirements.txt` | Python-залежність: пакет `groq`. |
| `.gitignore` | Не дозволяє Git додати `.env` або Python-кеш. |
| `logs/ai_assist.log` | Локальний журнал запусків, стану веб-пошуку та помилок. |
| `chats/chat_*.json` | Локально збережена історія кожного діалогу. |

## Збереження історії чатів

Після кожної успішної відповіді програма автоматично оновлює JSON-файл у каталозі `chats`. Один запуск створює один файл чату; команда `/clear` починає новий діалог і новий файл, не видаляючи попередній.

Введіть `/history`, щоб побачити десять останніх збережених файлів. Їх можна відкрити будь-яким текстовим редактором. У файлах зберігаються системне повідомлення, ваші запити та відповіді моделі, але не API-ключ. Каталог `chats` виключено з Git через `.gitignore`.

Оскільки історія містить текст ваших повідомлень, не копіюйте ці JSON-файли у публічні місця без перевірки їхнього вмісту.

## Журнал роботи

Після першого запуску програма створює файл `logs/ai_assist.log`. У ньому фіксуються запуск і завершення програми, очищення чату, успішні відповіді, використання веб-пошуку та коди помилок.

Тексти запитів, відповіді та API-ключ не записуються. Коли журнал досягає 1 МБ, створюється новий файл, а зберігаються лише три попередні копії.

## Усунення проблем

### `GROQ_API_KEY не заданий`

Перевірте, що `.env` лежить поруч із `config.py` та має непорожній рядок:

```env
GROQ_API_KEY=...
```

Після зміни `.env` перезапустіть програму.

### `429` або «Перевищено ліміт Groq»

Це ліміт безкоштовного плану або занадто часті запити. Зачекайте й повторіть спробу; поточні ліміти видно в [Groq Console](https://console.groq.com/docs/rate-limits).

### `413 Request Entity Too Large`

Введіть `clear`, перезапустіть програму та повторіть один короткий запит. Код уже обмежує обсяг історії, тому така помилка не має накопичуватися в довгому чаті.

### Немає з’єднання з Groq

Перевірте інтернет, коректність ключа та статус Groq. Пакет можна перевстановити командою:

```powershell
python -m pip install -r requirements.txt
```

## Обмеження

- Доступність моделей, веб-пошуку та ліміти Groq можуть змінюватися.
- Веб-пошук допомагає отримати актуальну інформацію, але відповіді варто перевіряти за наведеними джерелами, особливо для важливих рішень.
- API-ключ належить конкретному Groq-акаунту й не повинен передаватися іншим людям.
